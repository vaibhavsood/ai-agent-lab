## Learned

**Lesson 1: what an agent is.**
- An LLM is stateless: text in, text out, no memory between calls.
- It can't do anything by itself. With tool calling it returns a structured
  request (`tool_use`), and my code decides whether to run it.
- The agent is the loop: call the model -> run the requested tool -> send the
  result back -> repeat until `stop_reason` is `end_turn`.
- Every call re-sends the whole `messages` list. That list is the agent's only memory.
- Each `tool_use` has an `id`, and the matching `tool_result` echoes it, so the
  model knows which result belongs to which request when it asks for several at once.

**Lesson 2: how the model picks a tool.**
- The model never sees tool code, only the name, description, and input schema.
- The description is the tool's user interface, and the model is the user.
