## Learned

- A program gets a copy of environment variables when it starts. Setting a
  variable doesn't update windows that are already open.
- Switching providers changed only the tool-schema wrapper and the model call.
  Tools, approval and loop logic didn't change.
- Gemini's Interactions API has the same three ideas as Claude: function_call
  with an id, function_result with that call_id, done when there are no more calls.
- Gemini can keep history on its server (`previous_interaction_id`); we resend
  it ourselves (`store=False`) so the history list stays visible.

## Problem

1. The error handler caught nothing: the Interactions API raises errors from a
   private module, not `google.genai.errors`.
2. My Anthropic key was typed in a terminal, so it's visible in the window and
   in PowerShell's history file.

## Fix

1. Read the HTTP status code from the exception instead of importing private classes.
2. Kept the key anyway (my choice). New keys go in through the Windows
   environment-variables dialog, not the terminal.

## Important insight

Docs and SDKs change quickly. Claude Code read Google's current docs and the
installed SDK's source instead of relying on memory, and that caught a new API
and a non-obvious error class.

## First real run (later the same day)

Set `GEMINI_API_KEY` and ran 02b on the lab: "How does
01-agent-from-scratch/agent.py decide when to stop looping?"

- Call 1: Gemini asked for `read_file` directly. It skipped list/search
  because the path was in my question.
- Call 2: with the file contents in history, it answered. No more function
  calls, so the loop stopped. Two model calls in total.
- The logic in the answer was correct (end_turn / refusal / max_tokens stop it,
  only tool_use continues, MAX_STEPS is the safety net).
- **The line numbers were wrong** (it said 151-158; the real checks start at
  161). `read_file` returns text without line numbers, so the model guessed,
  even though the system prompt asks it to cite line numbers.

**Insight:** an agent is only as accurate as its tools' output. When it gets
something wrong, check what the tools gave it before blaming the model.
Possible fix: prefix each line in `read_file` with its number.
